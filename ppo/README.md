# Territory Control 의도 공유 PPO

`territory_v1`의 `feedback` 전략에서 팀원 세 명이 정책 가중치를 공유한다. 첫 번째 헤드는 각자 이번 틱 행동을 제안한다. 두 번째 헤드는 자기 관측과 동결된 아군 제안 세 개를 보고 최종 행동을 선택한다. 두 수집 회차에서 환경의 물리 상태는 고정되고, 최종 제출 뒤에 한 틱 진행한다.

`policy.py`는 관측 인코더·제안 헤드·최종 행동 헤드·가치 헤드를 정의한다. `rollout.py`는 환경의 세션 API를 사용해 양쪽 회차에서 마스크를 적용하고 실행 코드를 변환한다. `trainer.py`는 당시 보았던 제안을 저장한 뒤 두 선택의 로그확률 합에 대해 에이전트 단위 PPO clipping을 적용한다. 가치 헤드는 제안 전 관측을 사용한다. GAE는 사망과 부활을 이어서 계산한다. 롤아웃 경계에서는 다음 관측의 가치로 bootstrap하고, 실제 경기 종료에서는 다음 가치를 0으로 둔다.

## 실행

저장소 루트에서 실행한다. 저장소가 지정한 PettingZoo 1.25.0과 호환되는 Python 3.13으로 가상환경을 만들 수 있다.

```sh
python3.13 -m venv ppo/.venv
ppo/.venv/bin/python -m pip install -e '.[test]' -r ppo/requirements.txt
ppo/.venv/bin/python -m pytest -q ppo/test_ppo.py

ppo/.venv/bin/python -m ppo train --output ppo/runs/team_seed7
ppo/.venv/bin/python -m ppo train --reward individual --output ppo/runs/individual_seed7
ppo/.venv/bin/python -m ppo train --hide-teammates --output ppo/runs/team_hidden_seed7
ppo/.venv/bin/python -m ppo evaluate ppo/runs/team_seed7/best.pt
```

기본값은 8×8 맵, 최대 128틱, 8개 환경에서 64틱씩 196회 수집(100,352 환경 틱), 학습 seed 7이다. 상대는 에피소드마다 `random`과 `expand` 중 하나로 고정되며, 학습 팀은 양 진영을 번갈아 맡는다. 팀 보상은 종료 승·무·패에 +1/0/−1, 개인 보상은 실제 점령 기여도다. 환경 설정과 PyTorch·NumPy 버전은 `config.json`에 기록한다.

`best.pt`는 고정 검증 경기에서 승리 1점·무승부 0.5점으로 계산한 평균 경기 점수가 가장 높은 시점이다. 동률이면 평균 최종 영역 차이로 선택한다. 같은 실행에 최초 `initial.pt`, 마지막 `latest.pt`, 학습 로그 `metrics.jsonl`도 저장된다.

`evaluate`는 검증용과 다른 seed를 사용하고, 각 seed에서 양 진영으로 한 번씩 경기한다. 기본 평가는 `random`, `expand`, 학습에 쓰지 않은 `aggressive`와 `defend`를 포함한다. 통신을 사용해 학습한 모델에는 자기 제안만 남기는 평가를 같은 seed로 추가한다. `mean_listening_tv`는 동일 관측에서 팀원 제안 두 개를 가렸을 때 최종 행동 분포가 바뀐 정도다. `--hide-teammates`로 처음부터 학습한 모델도 같은 평가 명령으로 비교할 수 있다.

## 이동 충돌과 엄호 평가

```sh
ppo/.venv/bin/python -m ppo.tactics ppo/runs/team_seed7/best.pt --output ppo/runs/tactics_repeat.json
```

같은 팀 보상 체크포인트에서 각 배치를 두 번 실행한다. 두 실행은 시작 상태, 상대 행동, 첫 제안이 동일하다. 제안 공유를 끄는 실행에서는 각 에이전트 자신의 제안만 최종 행동 헤드에 전달한다. 두 모드 모두 확률이 가장 높은 행동을 고른다.

- **이동 충돌**은 두 아군이 인접한 빈 아군 타일을 목표로 할 수 있게 배치한다. 상대는 정지한다. 환경이 목표 칸 이동에 `contested`를 기록한 경우를 충돌로 센다. 한 명이 해당 칸으로 이동에 성공한 비율도 함께 센다.
- **엄호**는 고정 상대가 아군이 서 있는 타일을 공격한다. 인접한 아군이 그 칸을 함께 공격하면 동률 규칙으로 타일을 지킬 수 있다. 목표 칸을 유지하고 보호 대상의 사망 이벤트가 없으면 성공이다.
- 전선 형태 2종, 양 진영, 목표 행 4개, 역할 배정 6개, 시점 3개, 접근 방향 2종, 쿨다운 상태 2종을 조합해 유형당 1,152개 시작 상태를 평가했다. 쿨다운 조건에서는 이동 상황의 아군 세 명 또는 엄호 대상 한 명에 한해 공격이 막힌다.
- 1차 PPO 제안을 그대로 쓰는 평가와, 목표 칸에 접근할 수 있는 두 아군에게 해당 칸으로의 이동 또는 엄호 공격을 제안하게 하는 평가를 각각 실행한다. 두 경우 모두 최종 행동은 PPO가 결정한다. 출력 JSON에는 조건별 집계와 각 시작 상태의 제안·최종 행동·판정이 담긴다.

학습 seed 7의 팀 보상 체크포인트(업데이트 120) 결과다. 각 행의 두 열은 같은 시작 상태 1,152개를 기준으로 한다.

| 제안 방식 | 지표 | 팀원 제안 공유 | 팀원 제안 가림 |
| --- | --- | ---: | ---: |
| PPO가 선택 | 이동 충돌 | 2/1,152 (0.17%) | 0/1,152 (0%) |
| PPO가 선택 | 목표 칸 도달 | 287/1,152 (24.91%) | 288/1,152 (25.00%) |
| PPO가 선택 | 방어 성공 | 576/1,152 (50.00%) | 576/1,152 (50.00%) |
| 이동·엄호 제안 지정 | 이동 충돌 | 1/1,152 (0.09%) | 0/1,152 (0%) |
| 이동·엄호 제안 지정 | 목표 칸 도달 | 288/1,152 (25.00%) | 288/1,152 (25.00%) |
| 이동·엄호 제안 지정 | 방어 성공 | 576/1,152 (50.00%) | 576/1,152 (50.00%) |

방어 성공은 두 모드 모두 후방에 엄호자가 있는 576개 상태에서 나왔다. 측면 엄호 상태 576개에서는 모두 실패했다. 이동 충돌은 모두 공격 쿨다운 중 후방과 측면에서 같은 칸에 접근할 수 있는 배치에서 일어났다.

## 맵 전이와 무부활 실험

```sh
ppo/.venv/bin/python -m ppo train --map-size 3 10 --canvas-size 8 10 --seed 7 --output ppo/runs/transfer_example
ppo/.venv/bin/python -m ppo evaluate ppo/runs/transfer_example/latest.pt --map-size 8 8 --respawn immediate --seed 400000 --pairs 8
ppo/.venv/bin/python -m ppo evaluate ppo/runs/transfer_example/latest.pt --map-size 8 8 --respawn none --seed 400000 --pairs 8
```

학습에도 무부활을 적용하려면 `train`에 `--no-respawn`을 넣는다. 기존 규칙의 부활 대기를 경기 최대 틱으로 설정하므로 사망 이후 경기 종료 전까지 돌아오지 않는다. 두 팀에 동일하게 적용하며, 승패와 시간 제한은 기존 환경 규칙을 따른다.

3×10과 8×8 관측은 공통 8×10 입력 가운데에 0으로 패딩한다. 실제 칸의 좌표 관계와 행동 마스크는 각 환경을 따른다. 맵·부활 조건만 바꿔도 같은 체크포인트를 평가할 수 있다. 파일럿은 3×10/8×8 × 즉시 부활/무부활의 네 학습 조건에 학습 시드 7, 19, 31을 사용한다. 조건과 시드마다 100,352틱 학습한 마지막 체크포인트를 별도 평가 시드 400000–400007에서 네 상대와 양 진영으로 평가한다.

### 협력 지표

협력의 단위는 팀원의 행동이 팀 목표나 다른 에이전트의 생존에 만든 차이다. `evaluate`는 보상과 별도로 다음 행동 사건을 센다.

- **이동 양보**는 둘 이상이 같은 빈 아군 칸을 제안한 상황에서, 제안자 한 명이 실제로 그 칸에 도달한 경우다. 아군끼리 같은 칸으로 움직여 실패한 시도와 전체 이동 성공률도 기록한다.
- **엄호**는 아군이 서 있는 타일을 상대가 공격하고, 공격 가능한 인접 아군 수가 상대 공격 수 이상인 경우를 기회로 센다. 아군의 대응 공격으로 상대가 타일 점령에 실패하면 엄호 성공이다. 아군 대응 공격을 제거했을 경우 그 타일이 점령되는지는 환경의 공격 판정식으로 확인할 수 있다.
- **필요했던 공동 점령**은 아군 둘 이상이 공격해 점령했고, 그중 하나를 빼면 동률이 되어 점령에 실패하는 사건이다.

성공 건수와 기회 수를 함께 보고, 기회가 0건이면 비율을 정의하지 않는다. 같은 체크포인트에서 팀원 제안만 가리는 평가는 위 행동이 통신에 얼마나 의존하는지 확인하기 위한 비교다. 두 실행의 행동이 달라지면 이후 상태와 기회 수도 달라질 수 있다.

### 결과

각 숫자는 팀원 제안을 공유했을 때의 경기 점수 `(승 + 0.5 × 무승부) / 192`다. 3×10은 높이 3, 너비 10이며, 기본 전선 배치에서 시작 시 세 행을 모두 사용한다.

| 학습 조건 | 3×10 즉시 부활 평가 | 3×10 무부활 평가 | 8×8 즉시 부활 평가 | 8×8 무부활 평가 |
| --- | ---: | ---: | ---: | ---: |
| 3×10 즉시 부활 | 44.8% | 75.0% | 24.7% | 66.4% |
| 3×10 무부활 | 41.1% | 75.0% | 26.3% | 67.4% |
| 8×8 즉시 부활 | — | — | 28.4% | 67.7% |
| 8×8 무부활 | — | — | 18.5% | 68.2% |

3×10 즉시 부활 학습 모델은 즉시 부활 환경에서 평가 맵을 8×8로 바꾸면, 세 학습 시드 모두 경기 점수가 낮아졌다. 3×10 무부활 학습 모델의 8×8 무부활 평가는 67승 125무였고, 그중 133경기는 아군 생존자가 0명이었다. 네 학습 조건 모두 8×8 무부활 평가에서 부활은 0건, 엄호 성공은 방어 가능한 타일 공격 204회 중 0건이었다.

3×10 즉시 부활 학습 모델의 8×8 즉시 부활 평가에서 팀원 제안을 보여주면, 팀원 제안을 가릴 때보다 아군 이동이 같은 칸에서 막힌 비율은 13.4% 대 15.3%, 엄호 성공률은 75.3% 대 72.9%였다. 경기 점수는 양쪽 모두 24.7%였다. 사건 비율은 각 실행이 실제로 방문한 상태의 기회 수를 분모로 사용했다.

원본은 `runs/map-respawn-seed*/`, 조건별·상대별·학습 시드별 집계는 `runs/map-respawn-summary.json`에 있다.

## MCS 송신자 행동 예측 손실

첫 번째 회차에 실제로 보낸 아군의 이산 행동 제안 하나로, 같은 송신자가 두 번째 회차에 제출한 최종 행동을 예측한다. 학습 손실은 `L_PPO + 0.1 × cross_entropy`다. 예측기는 제안의 one-hot 하나를 입력으로 받는다. 역전파에서는 제안 확률에 대한 straight-through gradient를 사용해 예측 손실을 제안 헤드에도 전달한다. 최종 행동 후보가 하나인 샘플은 예측 손실과 예측 정확도 집계에서 제외한다. 정책의 추론 경로는 기존 제안 공유 구조를 사용한다. [MCS 원문 §4.2–4.3](https://arxiv.org/html/2511.03348#S4.SS2)

```sh
ppo/.venv/bin/python -m ppo train --map-size 3 10 --canvas-size 8 10 --seed 7 --sender-prediction-coef 0.1 --output ppo/runs/mcs_example
ppo/.venv/bin/python -m ppo evaluate ppo/runs/mcs_example/latest.pt --map-size 8 8 --respawn immediate --seed 400000 --pairs 8
```

학습 조건 네 가지와 학습 시드 7, 19, 31에서 각 100,352틱을 사용했다. 기존 비교와 같은 마지막 체크포인트, 평가 시드, 상대, 양 진영을 사용했다. 공유 끔은 평가 때 팀원 두 명의 제안을 가리고 자기 제안을 유지하는 조건이다. 충돌률은 전체 아군 이동 시도 중 같은 칸을 노린 아군과 충돌한 시도의 비율이다. 엄호 성공률은 대응 가능한 아군이 충분한 상황에서 적의 점령을 막은 비율이다.

## 수신자 PPO 손실의 송신자 역전파

`--backpropagate-messages`는 수신자가 실제로 받은 이산 제안에 straight-through gradient를 연결한다. PPO 미니배치의 각 수신자에 대해 같은 경기·같은 틱의 팀원 관측에서 송신자의 제안 확률을 다시 계산한다. 순전파와 PPO 확률비 계산에는 롤아웃에 기록된 one-hot 제안을 사용하고, 역전파에서는 새 제안 확률을 통해 수신자의 정책 손실이 송신자 제안 헤드와 상태 인코더에 전달된다. 이 경로는 수신자에게 공개된 팀원 슬롯에 적용된다. 송신자 행동 예측 손실의 가중치도 0.1로 유지한다.

```sh
ppo/.venv/bin/python -m ppo train --map-size 3 10 --canvas-size 8 10 --seed 7 --sender-prediction-coef 0.1 --backpropagate-messages --output ppo/runs/mcs_backprop_example
ppo/.venv/bin/python -m ppo evaluate ppo/runs/mcs_backprop_example/latest.pt --map-size 8 8 --respawn immediate --seed 400000 --pairs 8
```

기존 PPO, 예측 손실만 추가한 PPO, 수신자 역전파까지 추가한 PPO의 마지막 체크포인트를 같은 12개 학습·평가 조합에서 비교한다. 모델별 학습 시드 3개에 각 100,352틱을 사용하고, 평가 때 공유 켬·끔 각각 192경기를 치른다. 승률, 무승부 가중 점수, 아군 충돌률, 엄호 성공률은 앞과 같은 기준으로 계산한다.
