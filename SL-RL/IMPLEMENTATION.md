# 구현 설명과 결정 기록

## 구현 범위

`SL-RL`에서 기존 `territory_rl` 패키지를 불러옵니다. 3vs3의 게임 진행은 `TerritoryEnvironment.reset/step`이 담당합니다. 1vs1은 원본이 ID 여섯 개, 세 명의 시작 행, 관측 슬롯 세 개를 전제로 하므로 별도의 두 명 진행기를 두었습니다. 같은 `Action`, `AgentState`, `TileMap`, 행동 마스크, 공격 집계, 동시 이동, 부활 처리를 재사용합니다. 1vs1에서 틱 진행 순서와 관측 연결은 별도로 유지해야 하므로 원본 규칙 변경 시 `verify.py`를 실행하고 변경된 전이 규칙도 대조하세요.

| 파일 | 주요 코드와 역할 |
|---|---|
| `run.py` | `main`이 pretrain/train/resume/evaluate/duel을 분기합니다. |
| `arena.py` | `Arena`는 팀 크기별 환경 선택과 점령률 보상을 담당합니다. `Duel`은 두 명만 참가하는 경기, `opening_row`는 시작 행 균형, `inputs`와 `reflect`는 정책 관측·행동 좌표 변환을 담당합니다. |
| `models.py` | `MapEncoder`는 점령 지도와 마스크를 잠재 벡터로 바꿉니다. `TeamPolicy`는 주변 개체의 표현을 만들고 Actor와 Critic을 계산합니다. |
| `pretrain.py` | `collect`는 기존 봇들의 경기에서 지도 수집, `sample_mask`는 칸 가리기, `validation`은 복원과 두 기준선 비교, `pretrain`은 학습·최적 인코더 저장을 수행합니다. |
| `training.py` | `decide`는 마스킹된 행동 선택, `trajectory`는 경기별·에이전트별 GAE, `update`는 팀별 PPO, `train`은 실행 폴더·재개·학습 지표를 담당합니다. |
| `evaluation.py` | `Player`가 인코더와 학습 팀 둘을 복구합니다. `match`는 3vs3 한 경기, `evaluate`는 상대·학습 팀·진영의 조합과 결과 저장을 담당합니다. |
| `storage.py` | 설정 검증, 새 폴더 번호 할당, 임시 파일 교체 방식의 체크포인트 저장, CSV·JSON 기록을 담당합니다. |
| `verify.py` | 실제 명령행으로 두 학습 조건을 실행하고, 연속 학습과 중단 후 재개의 가중치가 같은지 검사합니다. |

## 지도 자기지도학습

1. 각 인원 조건에서 random·expand·aggressive·defend의 순서 있는 16개 진영 조합을 16경기마다 섞습니다. 학습과 검증 경기는 다른 난수 스트림으로 생성합니다. 각 경기에서 시작과 종료를 포함한 등간격 틱을 뽑고 두 팀 관점으로 표현합니다. 매우 짧은 경기에서는 같은 틱이 다시 선택될 수 있습니다.
2. 기본 설정은 160경기 중 학습 128·검증 32경기, 경기당 12틱 × 두 관점입니다. 3vs3 팀원이 세 명이라고 같은 소유권 지도를 세 번씩 추가하지 않습니다.
3. 30칸 소유권과 마스크 30칸을 연결해 `60 → 64 → 16` MLP에 넣습니다. 디코더는 `16 → 64 → 30`이며 가려진 9칸의 이진 교차엔트로피만 줄입니다. 각 epoch의 학습 마스크는 갱신하고 검증 마스크는 고정합니다.
4. 경계는 상하좌우 중 적어도 한 칸의 소유 팀이 다른 칸입니다. 다수결 기준선은 보이는 상하좌우만 세고 동률이면 시작 지도 값을 사용합니다. 분모가 0인 전선 정확도는 CSV에서 빈칸입니다.
5. 인원별 검증 손실이 가장 낮은 epoch의 인코더를 저장합니다. PPO에서는 가리지 않은 지도와 전부 0인 마스크를 입력하고 인코더를 동결합니다. 평가 시에도 해당 run에 저장된 동일 인코더를 씁니다.

## PPO와 관측

양 팀은 매 경기 자기대전으로 각각 학습합니다. 한 팀의 정책을 모든 팀원이 공유하며 반대 팀은 독립적인 파라미터를 가집니다. 각 에이전트는 지도 특징, 자신의 행·열, 남은 시간, 생존·공격 가능·부활 대기 정보, 타 개체의 상대 위치·소속·상태를 사용합니다. 주변 개체마다 같은 가중치를 적용한 뒤 평균을 내고 주변 개체의 총수를 함께 전달합니다. 아군·적군 구분은 각 개체의 소속 값으로 전달합니다. 1vs1에서 항상 0인 아군 전용 입력 열을 따로 학습시키지 않습니다. 3vs3에서 처음 접하는 아군의 존재와 수적 차이는 여전히 전이 성능에 영향을 줄 수 있습니다. 팀원 식별번호나 이번 틱의 타인 행동을 정책에 주지 않습니다. 양 진영은 자기 출발지가 왼쪽이 되도록 지도·위치·행동 마스크를 맞추고, 제출할 행동은 실제 방향으로 돌려놓습니다.

`inputs`는 한 틱의 스냅샷에서 각자의 공개 관측으로 복구할 수 있는 항만 계산합니다. 현재 원본은 어느 위치에서든 전체 맵을 보여 줍니다. 사망한 다른 개체의 마지막 위치는 제외하고 그 개체의 생존·대기 상태는 유지합니다. 지도 소유권에 생존자가 서 있는 칸은 항상 해당 팀 땅입니다. 시야 제한·은닉 정보가 도입되면 이 입력 변환도 함께 검토해야 합니다. Critic은 Actor와 동일한 관측을 사용합니다.

팀별로 행동을 샘플링하고 이전 로그 확률과 가치를 저장합니다. 각 에이전트에 대해 `δ = r + γV(next) − V(now)`, `A = δ + γλA(next)`를 경기 끝에서부터 계산합니다. 64틱은 이 과제의 승부가 결정되는 끝이므로 마지막 후속 가치는 0입니다. 부활 가능한 사망에서는 궤적을 이어갑니다. 두 팀을 분리하여 PPO 비율 clipping, advantage 정규화, 가치 오차, entropy 보너스를 적용합니다. 정지만 가능한 틱은 행동·entropy 손실과 advantage 정규화에서 제외하고 가치 학습과 보상 누적에는 포함합니다. `approx_kl`은 업데이트 도중 행동 선택이 가능했던 표본의 `ratio − 1 − log(ratio)` 평균입니다. 근사 KL이 작아도 승률은 별도로 확인해야 합니다.

학습 보상은 `행동 후 팀 점령 칸 수 / 전체 칸 수 + α × 개인 점령 기여 횟수`입니다. 기본 α는 1입니다. 두 조건 모두 종료 보너스와 사망 패널티는 0이며, 사망 중에도 팀 점유율 항을 지급합니다. 승부는 종료 시점 점령 칸 수를 비교합니다.
