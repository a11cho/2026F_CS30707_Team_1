```python
import numpy as np
def derived_seed(master, domain, index=0):
    return int(np.random.SeedSequence([master, domain, index]).generate_state(1)[0])

# 학습 에피소드 i = 0..79
env_seed = derived_seed(master, 10, i)
policy_seed = derived_seed(master, 11, i)
# 학습 역할 j의 행동 RNG / 전체 ID 인덱스 k의 봇 RNG
learner_rng_seed = derived_seed(policy_seed, 1, j)
bot_rng_seed = derived_seed(policy_seed, 2, k)
# validation pair p = 0..9 / test pair p = 0..29
val_env = derived_seed(20261031, 20, p)
val_policy = derived_seed(20261031, 21, p)
test_env = derived_seed(20261031, 30, p)
test_policy = derived_seed(20261031, 31, p)
```

## 9. 토의할 질문과 다음 실험 우선순위

1. **수렴을 먼저 볼 수 있는 작은 문제로 만들 것인가?** 학습자 하나·고정 전술 배치·짧은 지평·더 작은 관측 key로 시작하면 MC/SARSA의 반복 방문과 가치 전파를 확인하기 쉽습니다. 현재 aware에서 예산만 늘리기 전에 표현의 재사용 가능성을 확인해야 합니다.

2. **정보 공유 비교에서 무엇을 고정할 것인가?** local/aware가 같은 길이여도 유효 key 수는 크게 다릅니다. 지금 결과를 정보 공유 자체의 이득/손해로 해석하지 말고, 팀원 정보의 더 거친 요약 또는 함수 근사를 별도 조건으로 검토할 수 있습니다.

3. **성공을 팀 승리와 개인 기여 중 무엇으로 판단할 것인가?** expand 아군 두 명이 random 상대를 압도할 수 있습니다. 학습자 자신의 점령 credit·행동·사망 원인과 아군 제거/교체 대조군이 필요합니다.

4. **학습 상대 분포를 바꿀 것인가?** random만으로 학습한 뒤 scripted 세 종류까지 일반화하기 어렵습니다. 먼저 train=random/test=random과 상대 일반화를 분리해서 보고, 이후 고정된 상대 혼합 분포를 사전 정의하는 것이 좋습니다.

5. **수렴을 측정할 로그를 넣을 것인가?** 일정 간격의 고정 greedy 평가, 같은 probe key 집합의 Q 변화, TD error/MC target 변화, key 방문 횟수, 생존/사망별 기방문률, 실제 행동 빈도, 프로세스 CPU/RAM과 phase별 타이머를 추가하면 논의가 훨씬 명확해집니다.

6. **최고 seed 선정과 알고리즘 비교를 분리할 것인가?** 배포용 대표는 validation으로 고르되 연구용 평균 test는 seed 5개 모두에서 보고해야 합니다. 현재 test를 본 후 변경하는 다음 실험에는 새로운 최종 hold-out bank를 마련해야 합니다.

7. **종료 보상·gamma·학습률을 어떻게 볼 것인가?** terminal SARSA의 값은 한 스텝씩 전파되고 짧은 학습·희소 재방문에서는 초반 행동까지 퍼지기 어렵습니다. 고정 alpha와 epsilon 설정 때문에 장기 학습만으로 엄밀 수렴을 보장하지 않습니다. 설정 변경은 이번 결과와 분리된 실험으로 기록하세요.
